# ADR 0002: 근거 기반 응답과 근거가 없을 때의 정책

- 상태: 제안 (아래 "결정"은 담당자가 정했고, 분류 방법·임계값·원천 목록은 열려 있습니다)
- 관련: [ADR 0001](0001-architecture.md)의 "근거 기반 응답", [평가 질문 세트](../evaluation/questions.md), 이슈 #6
- 범위: 답변이 어떤 근거에 기대는지, 근거를 찾지 못했을 때 무엇을 보여 주고 어떻게 답하는지. 검색 구현(색인, 임베딩, 검색 서비스 선택)은 이 문서의 범위가 아닙니다.

근거 표시는 [ui-ux.md](../ui-ux.md)와 같습니다.

## 배경

- 이슈 #6 시점의 채팅은 검색 단계가 없습니다. 모델이 혼자 답하므로 출처는 항상 비어 있습니다. 그런데 화면이 이를 "근거를 찾지 못했습니다"로 표시해, 시도하지 않은 일을 실패한 것처럼 보이게 했습니다. 이 표시는 검색 신호가 있을 때만 쓰도록 고쳤습니다.
- 문서 Q&A 서비스는 검색 후 생성, 인용, 근거가 없으면 모른다고 답하는 구조입니다 `[벤더]` [kapa.ai](https://docs.kapa.ai/use-cases/documentation-assistant). Stack Overflow AI Assist는 검색을 먼저 하고 없을 때만 모델 생성으로 넘어갑니다 `[벤더]` [출처](https://stackoverflow.blog/2025/12/02/introducing-stack-overflow-ai-assist-a-tool-for-the-modern-developer/).
- 코딩 환각의 주된 원인은 낡은 정보라고 보고됩니다 `[벤더]` [Mintlify](https://www.mintlify.com/library/ai-hallucinations).

## 결정 (담당자)

1. **기본은 근거 기반입니다.** 질문마다 먼저 근거를 찾고, 찾은 근거에 기대어 답하며 출처를 붙입니다.
2. **근거가 없을 때는 질문 유형으로 나눕니다.**
3. **근거의 원천에는 외부 공식 문서를 포함합니다.** 포트폴리오 문서와 함께 쓰는지, 어떤 문서를 쓰는지는 열려 있습니다.

## 근거가 없을 때의 정책

질문을 두 유형으로 봅니다. 분류 기준은 `[가정]`이며 평가로 조정합니다.

| 유형 | 질문의 성격 | 근거가 없을 때 | 화면 상태 |
| --- | --- | --- | --- |
| 일반 지식형 (G) | 개념 설명, 코드 리뷰, 오류 해결처럼 일반 지식으로 답할 수 있고 틀려도 사용자가 검증하기 쉬운 질문 | 답변합니다. 근거가 없었음을 표시합니다. | "출처 없이 생성된 답변입니다" |
| 사실·최신형 (F) | 버전, 릴리스, API의 존재·폐기, 한도·가격, 존재 여부를 모르는 식별자(오류 코드 등)처럼 틀리면 해롭고 낡은 정보가 흔한 질문 | 답변을 만들지 않습니다. 공식 문서 확인을 안내합니다. | "근거를 찾지 못했습니다" |

근거가 있을 때는 출처가 있는 상태로 보이며, 세 상태는 화면에서 서로 구분됩니다.

| 상태 | 언제 | 표시 |
| --- | --- | --- |
| 출처 있음 | 근거를 찾았고 인용했을 때 | 출처 목록(접힘) |
| 출처 없이 생성 | G 유형이고 근거가 없을 때 | "출처 없이 생성된 답변입니다" |
| 근거 없음 | F 유형이고 근거가 없을 때 | "근거를 찾지 못했습니다"와 공식 문서 확인 안내, 생성 답변 없음 |
| (검색 안 함) | 검색 단계가 없는 응답 | 아무것도 표시하지 않음 |

원칙은 다음과 같습니다.

- "근거를 찾지 못했습니다"는 검색을 했는데 없었을 때만 씁니다.
- "출처 없이 생성된 답변입니다"는 사용자가 답을 스스로 검증해야 한다는 신호이며, 틀릴 수 있다는 일반 안내([ux-checklist.md](../ux-checklist.md))를 대신하지 않습니다.
- 출처 링크는 `http(s)`만 링크로 만듭니다(이미 구현됨).
- 근거가 있지만 질문과 관련이 약한 경우의 처리는 임계값이 필요하며 평가로 정합니다. `[가정]`

## 외부 공식 문서를 쓸 때의 조건

원천에 외부 문서를 넣으면 다음을 구현 전에 확인해야 합니다. 아래는 모두 아직 확인하지 않았습니다.

- **라이선스와 이용 약관**: 각 문서의 색인·재배포·요약 인용이 허용되는지. 허용되지 않으면 원천에서 제외하거나 링크만 제공합니다.
- **허용 목록**: 색인하는 도메인을 목록으로 관리하고, 목록 밖은 쓰지 않습니다. `[가정]`
- **간접 프롬프트 인젝션**: 외부 문서 안에 모델에 대한 지시가 있을 수 있습니다. 검색된 내용은 지시가 아니라 데이터로만 취급하게 하고, 모델에는 도구 호출이나 코드 실행 능력을 주지 않아 영향 범위를 좁힙니다. 이 방어가 충분한지는 검증하지 않았습니다. `[가정]`
- **갱신 주기**: 문서가 바뀌면 답이 낡습니다. 색인 날짜를 답변에 표시하고 갱신 주기를 정합니다. 최신성이 이 정책의 핵심 이유라서 갱신 실패는 F 유형의 "근거 없음"으로 이어지게 합니다. `[가정]`
- **질문의 외부 전송**: 검색 서비스를 외부로 쓰면 사용자 질문이 외부로 전송됩니다. 서비스를 고를 때 보관 정책을 확인합니다.
- **한국어 질문**: 한국어 기술 질문의 검색 품질에 대한 근거를 찾지 못했습니다. 평가 질문 세트의 한국어 유형(E)으로 확인합니다.

## 열린 질문 (구현 전에 정해야 함)

| 질문 | 후보 | 정하는 방법 |
| --- | --- | --- |
| G/F 분류를 누가 하나 | (a) 규칙(버전 숫자, "최신", "deprecated" 등) (b) 모델에게 분류 호출 (c) 시스템 프롬프트로 모델이 판단 | 평가 질문 세트로 정확도와 지연을 측정. (b)는 호출이 한 번 늘어 첫 토큰이 늦어집니다. |
| 근거가 있다고 볼 최소 관련도 | 점수 임계값 | 평가에서 C5와 D 유형의 오분류율로 조정 |
| 근거 없음(F)일 때 안내 문구와 링크 | 공식 문서 홈, 검색어 제안 | 담당자 확인 |
| 외부 문서 목록과 라이선스 | React, Next.js 등 | 위 "조건"을 확인한 뒤 담당자 결정 |
| 검색이 늘리는 지연의 허용치 | 첫 토큰 목표값 | 구현 후 측정해 담당자와 결정 |

## 검증 방법

[평가 질문 세트](../evaluation/questions.md)로 검색을 켠 경우와 끈 경우를 같은 조건에서 비교합니다. 이 비교는 후보 구성 간 우열 비교가 아니라, 정책이 의도대로 동작하는지 확인하는 ON/OFF 검증입니다.

- F 유형으로 취급되는 질문(D 유형, C5)에서 근거가 없을 때 답을 지어내지 않고 "근거를 찾지 못했습니다"로 끝나는지
- G 유형 질문(A, B, C1~C4, E)에서 근거가 없어도 답하고 "출처 없이 생성된 답변입니다"가 붙는지, 불필요한 "근거 없음"이 얼마나 나오는지
- 근거가 있을 때 출처 링크가 열리고 주장과 맞는지(출처 유효성)
- 검색이 늘린 첫 토큰·전체 시간

## 결과와 한계

- 이 정책은 담당자의 선택이며 비교 평가한 결과가 아닙니다. 질문 유형 분기가 실제로 더 낫다는 근거는 아직 없습니다.
- G/F 분류가 틀리면 F 질문에 지어낸 답이 나가거나 G 질문이 불필요하게 막힐 수 있습니다. 분류 방법에 따라 지연과 비용이 달라집니다.
- 근거 원천의 라이선스와 인젝션 방어는 확인 전입니다. 확인 결과에 따라 외부 문서가 원천에서 빠질 수 있습니다.
