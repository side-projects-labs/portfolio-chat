# QA

## 범위 파악

`git status`, `git diff` (브랜치 단위면 `git diff origin/master...HEAD`)로 변경 파일을 확인한다. 브랜치 비교 전 `git fetch origin`을 수행하고 기준 SHA를 기록한다. 이슈 본문·댓글 또는 사용자 요구의 기대 동작과 제약을 먼저 확인한다.

## 1단계: 정적 검증

기술 스택이 아직 정해지지 않았다. `package.json`이 있으면 거기에 **실제로 있는** lint·타입 검사·빌드 스크립트만 실행한다. 없는 명령을 다른 저장소에서 가져오지 않는다.

- `package.json`이 없으면 "생략 (스택 없음)"으로 기록하고 통과로 쓰지 않는다
- 빌드가 외부 API나 환경변수를 필요로 해 실행하지 못했으면 이유와 함께 "생략"으로 적는다
- 자동 수정 명령(`--fix` 등)은 사용자가 요청했을 때만 쓰고, 수정된 파일을 리포트에 명시한다

## 2단계: 테스트

저장소에 있는 테스트 스크립트를 실행하고 변경 경로만 먼저 돌린다.

- 변경된 로직에 대응 테스트가 없으면 "테스트 누락"으로 기록한다 (필요 시 `tdd` 스킬 제안)
- 기존부터 실패하던 테스트는 이번 변경과 구분해 기록한다
- 테스트가 실제 네트워크, 실제 키, 실제 대화 내용에 의존하지 않는지 확인한다

## 3단계: 문서·설정 변경 검증

문서와 설정만 바뀌면 다음을 확인한다.

- 문서가 참조하는 파일 경로와 링크가 실제로 있는지, 심볼릭 링크가 `SKILL.md`로 연결되는지
- 비밀값 패턴(키, 토큰, 인증서, 개인정보)이 없는지. 공개 저장소이므로 반드시 확인한다
- 지침이 서로 모순되지 않는지(`AGENTS.md`와 진입점 요약)

## 4단계: 코드 리뷰

`review` 스킬을 staged/branch/local 중 실제 변경 범위에 맞게 실행하고 발견 사항을 리포트에 그대로 옮긴다. 일반 QA는 PR 댓글을 자동 작성하지 않는다. 중요한 미확인은 검증 보류에 해당하는 차단 사항으로 기록한다.

## 리포트 형식

```markdown
## QA 결과: <통과 | 조건부 통과 | 실패>

| 항목 | 결과 | 비고 |
| --- | --- | --- |
| Lint | ✅/❌/생략 | |
| 타입 체크 | ✅/❌/생략 | |
| 빌드 | ✅/❌/생략 | |
| 테스트 | ✅/❌/생략 | n passed / m failed |
| 문서·민감정보 검증 | ✅/❌/해당 없음 | |

### 발견 사항

- 🔴 반드시 수정: <파일:라인 - 내용>
- 🟡 권장: <내용>
- 🟢 참고: <내용>

### 다음 단계

<수정 필요 항목 또는 commit/pr 진행 제안>

### 불변조건과 미확인 사항

- <실행하지 못한 검증, 판정 영향과 필요한 최소 추가 검증을 적습니다.>
```

발견 사항과 생략 이유처럼 근거를 남기는 문장은 `~습니다`로 끝낸다. 발견 사항은 보고만 하고, 수정은 사용자가 요청하거나 명백한 린트 자동수정에 한해 진행한다.
