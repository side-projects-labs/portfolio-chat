# Code Review

## 범위와 권한

| 모드 | 검토 대상 |
| --- | --- |
| staged | `git diff --staged`와 관련 호출 경계를 확인합니다. 미스테이징 파일에 의존해야 통과하는 변경인지 구분합니다. |
| branch | `git fetch origin` 후 실제 PR base 대비 `git diff origin/<base>...HEAD`를 확인합니다. 원격 PR head와 로컬 HEAD의 일치 여부를 확인합니다. |
| local | QA 또는 미커밋 리뷰에서 `git diff --staged`, `git diff`, `git ls-files --others --exclude-standard`의 관련 내용을 각각 확인합니다. |

- 이 저장소에는 CI 리뷰 워크플로가 없으므로 리뷰는 로컬 에이전트가 실행합니다.
- base/head SHA 또는 로컬 작업 상태, 모드, 제외 범위를 기록합니다. 다른 PR을 리뷰하려고 현재 브랜치를 전환하지 않습니다.
- lockfile, 빌드 산출물, 생성 파일의 본문은 기본 제외하되 의존성·출력 계약의 영향은 manifest와 소비자에서 확인합니다.
- 리뷰는 보고만 수행합니다. 수정·커밋·푸시·PR 생성·머지는 각각 사용자 요청과 해당 스킬이 필요합니다.
- 인증값과 개인정보 원문을 출력하거나 리뷰에 복사하지 않습니다.

## 1. 목적과 계약

- 연결된 이슈의 본문·댓글, PR 설명, 사용자 지시에서 기대 동작, 수용 조건, 금지 사항과 변경 범위를 정리합니다. 구현자의 설명은 코드로 확인할 가설로 취급합니다.
- 필요한 자료를 읽지 못했다면 판단에 미치는 영향을 기록합니다. 범위를 벗어난 변경의 근거와 실제 영향을 확인합니다.
- 기존 리뷰 댓글과 미해결 스레드는 최신 head에서 재검증합니다. 불완전한 조회를 전체 확인으로 간주하지 않습니다.
- portfolio2에서 코드를 옮기는 PR이면 원본 경로와 기준 커밋이 적혀 있는지, 이전과 동작 변경이 섞이지 않았는지 확인합니다.

## 2. 데이터 흐름과 공통 소유권

- 사용자 입력 → 검증·정규화 → 모델 호출 → 응답 처리 → 상태·화면의 경로를 추적합니다. 관련 없는 경계는 억지로 확장하지 않습니다.
- 같은 개념의 병렬 모델, 변환 로직 복제, 원본과 파생 상태의 이중 소유를 확인합니다. 근거 없이 호환 분기·조용한 복구·재시도를 권하지 않습니다.

## 3. 불변조건과 영향 시나리오

관련 항목만 골라 확인·위반·미확인·해당 없음으로 구분합니다. 테스트 통과만으로 전체 경계를 확인했다고 쓰지 않습니다.

- **공개 저장소의 비밀값·내부 정보**: API 키, 토큰, 인증서, `.env*`, 개인정보, 실제 사용자 대화가 코드·테스트·문서·로그·커밋 메시지에 없는지 확인합니다. 시스템 프롬프트와 프롬프트 문서를 공개해도 되는지 확인합니다.
- **AI 호출의 키와 입력**: 키를 서버에서만 읽고 클라이언트 번들로 보내지 않는지, 사용자 입력의 길이·형식을 모델에 보내기 전에 검증하는지, 프롬프트 인젝션으로 시스템 지침이나 키가 노출되지 않는지 확인합니다.
- **오류와 응답 처리**: 모델 실패·시간 초과·비정상 응답에서 사용자에게 안전한 오류가 가고 키·내부 주소·스택·응답 원문이 새지 않는지, 부분 응답과 빈 응답을 처리하는지 확인합니다.
- **상태와 비동기**: 응답이 뒤바뀌어 도착해도 오래된 응답이 최신 상태를 덮지 않는지, 중복 요청, 실패 후 상태, 로딩·빈 값·오류 상태를 확인합니다.
- **설정·의존성**: 모듈 해석, 번들·빌드·런타임, 환경변수 경계, 새 의존성의 필요성과 출처를 확인합니다. 문서·설정의 TDD 예외는 운영 영향 검토의 면제가 아닙니다.
- **라이선스와 PROJECT.md**: 담당자 확인 없이 추가되지 않았는지 확인합니다.

보안·데이터 손실·공개 노출 등 중요한 경계를 검증하지 못했다면 필요한 최소 검증을 지정합니다.

## 4. 코드와 테스트 근거

- 비밀값 하드코딩, `.env*` 포함, 클라이언트 번들로의 키 노출, 검증되지 않은 `dangerouslySetInnerHTML`·마크다운 렌더링 입력(모델 응답 포함), 오류 응답의 스택·키·내부 URL 노출을 우선 확인합니다.
- 실행 동작 변경에 대응하는 테스트가 없으면 TDD 규칙 위반으로 차단합니다. 파일 존재만 보지 말고 수용 조건과 경계 동작을 검증하는지, 입력을 가공해서 읽는 assertion이 서로 다른 구현을 구분하는지 확인합니다.
- 테스트의 실제 네트워크·실제 키·현재 시각·순서 의존, assertion 약화를 확인합니다. TDD 순서의 증거 없이 Red를 실행했다고 추정하지 않습니다.
- 발견마다 코드 위치, 위반 계약, 발동 조건·영향과 테스트 근거를 적습니다. 테스트 항목은 기존 케이스·실행 결과, 검색으로 확인한 누락, 또는 구체적인 재현 방법으로 채우고 미실행은 명시합니다.
- 문서·설정 등 TDD 예외는 파일과 이유를 기록합니다. 코드·계약 근거 없는 결함은 지적하지 않습니다. 개발 서버는 자동으로 띄우지 않습니다.

## 5. 심각도와 결론

- **차단**: 확인된 보안 문제(비밀값·개인정보 공개 포함), 데이터 손상·손실, 명백한 동작 오류, 테스트 없는 실행 동작 변경을 보고합니다. 중요한 로컬 검증 경계의 판단 근거가 빠진 경우는 결함 확정과 구분해 검증 보류로 보고합니다.
- **권장**: 코드 근거가 있는 비차단 경계 누락, 유지보수 개선을 보고합니다.
- **참고**: 동작을 바꾸지 않는 사소한 의견만 적습니다. 취향과 추측은 제외합니다.
- 결론은 🔴 수정 필요, 🔴 검증 보류, 🟡 권장 사항 있음, ✅ 문제 없음 중 하나입니다. 중요한 미확인 항목이나 잘린 diff가 남으면 ✅ 문제 없음으로 결론 내리지 않습니다.
- 머지 전 확인은 본문 전체에서 차단 아이콘을 검색합니다. 차단이 없는 결과에는 해당 아이콘을 범례·선택지·해소된 과거 지적에도 남기지 않습니다.

## 출력과 후속 처리

- 결과는 [TEMPLATE.md](TEMPLATE.md)만 채웁니다. 한국어 근거 문장은 ~습니다 또는 ~ㅂ니다로 끝냅니다. 해당하지 않는 섹션도 이유 또는 없습니다로 채웁니다.
- PR 댓글 첫 줄은 `<!-- ai-review:local -->`입니다.
- staged는 차단 시 커밋을 중단합니다. branch는 PR 생성·갱신 흐름에서 댓글로 남깁니다. 일반 local QA는 외부 댓글을 자동 작성하지 않습니다.
- 수정 요청으로 구현했다면 관련 TDD·QA 이후 새 SHA에서 목적·diff·영향 경계·검증을 다시 리뷰합니다. 이전 판정만으로 완료를 선언하지 않고, 자동 수정·커밋 반복 루프를 시작하지 않습니다.
- 머지는 `pr` 스킬을 따릅니다. 최신 리뷰의 차단 해소가 필요합니다.
