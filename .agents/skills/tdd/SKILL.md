# TDD (Red → Green → Refactor)

## 이 저장소의 전제

- 기술 스택과 테스트 러너는 아직 정해지지 않았다. `package.json`이 생기기 전에는 실행할 수 있는 테스트가 없다는 사실을 보고하고 통과로 쓰지 않는다.
- 러너가 정해지면 `package.json`의 스크립트와 설정 파일을 읽어 실제 명령을 확인한다. 다른 저장소(portfolio2 등)의 명령과 설정을 그대로 가져오지 않는다.
- 이 저장소는 공개다. 테스트와 fixture에는 실제 API 키, 토큰, 개인정보, 실제 대화 내용을 쓰지 않고 가짜 값을 쓴다.

## 요구사항과 소유권

- 연결된 이슈의 본문·댓글 또는 사용자 요구에서 기대 동작, 불변조건과 금지 사항을 확인한다. 확인된 사실과 구현 후보를 구분한다.
- 각 요구사항을 정상·경계·실패 시나리오, 구현 소유자, 대응 테스트에 연결한다. 이슈에 없는 요구를 임의로 추가하지 않는다.
- 기존 모델·타입·정책·공통 함수를 검색하고 올바른 소유자에서 수정한다. 같은 규칙을 호출자마다 복제하지 않는다.
- portfolio2에서 코드를 옮기는 작업이면 옮기기 전에 원본의 테스트를 확인하고 함께 옮긴다. 이전 PR은 동작을 바꾸지 않는다.

## 체크리스트

```
- [ ] 1. 요구사항을 테스트 케이스 목록으로 정리 (정상/경계/예외)
- [ ] 2. Red: 실패하는 테스트 1개 작성 → 실패 확인
- [ ] 3. Green: 테스트를 통과하는 최소 구현 → 통과 확인
- [ ] 4. Refactor: 중복 제거/정리 → 여전히 통과 확인
- [ ] 5. 남은 케이스에 대해 2~4 반복
- [ ] 6. 관련 테스트와 저장소에 있는 lint·타입 검사 실행
```

## 원칙: 코드 수정 = 테스트 추가/수정

- 수정한 파일마다 대응하는 테스트를 확인한다. 없으면 만들고, 있으면 변경된 동작에 맞게 케이스를 추가하거나 기대값을 고친다.
- 동작이 바뀌면 그 동작을 검증하는 케이스가 있어야 하고, 버그 수정에는 해당 버그를 재현하는 케이스가 있어야 한다.
- 문서(`*.md`), 설정, 스타일만 바꾸는 경우는 예외다. 대신 완료 보고에 테스트를 추가하지 않은 파일과 그 이유를 적는다.
- 테스트 없이 구현만 바뀐 상태로 작업을 끝내지 않는다.

## 규칙

- 구현 코드보다 테스트를 **먼저** 작성하고 실패를 실제로 확인한다. 미구현 동작이나 재현한 기존 버그 때문에 기대 결과가 어긋나야 한다. 의존성 누락·잘못된 import·테스트 설정 오류는 Red 증거가 아니다.
- 한 사이클에 테스트 1개만 추가하고, Green에서는 통과시키는 데 필요한 코드만 쓴다. 테스트를 통과시키려고 기대값을 바꾸지 않는다.
- 통과만을 위한 fallback, 조용한 재시도, 테스트 전용 분기, 타입 단언으로 원인을 덮지 않는다.
- 입력을 가공해서 읽는 assertion은 서로 다른 구현을 구분하지 못할 수 있다. 테스트가 기존 결함을 실제로 잡는지 확인한다.
- 이미 동작하는 코드를 고정하는 특성 테스트는 먼저 실패하는 상태가 없다. 그 경우 코드를 일부러 망가뜨려 테스트가 실패하는지 확인(변이 검사)하고 보고한다.
- AI 호출은 실제 네트워크와 실제 키에 의존하지 않는다. 모델 응답은 모의하고, 시간·난수·환경변수는 고정하며 테스트 뒤 복원한다.

## AI 채팅에서 우선 검증할 경계

- 사용자 입력의 빈 값, 너무 긴 값, 허용되지 않은 형식을 모델에 보내기 전에 걸러내는가
- 모델이 실패하거나 시간 초과하거나 비정상 응답을 줄 때 사용자에게 안전한 오류가 가고, 키·내부 주소·스택·응답 원문이 새지 않는가
- 대화 상태가 응답 순서가 뒤바뀌어도(먼저 보낸 요청이 늦게 도착) 오래된 응답으로 덮어쓰이지 않는가

## 실행 근거

- 각 사이클의 테스트 이름, 명령, 종료 코드, 실패 원인 또는 통과 결과를 기록한다. 실제로 실행하지 않은 결과를 Red·Green으로 보고하지 않는다.
- 로그에 비밀값·환경변수 원문·개인정보가 들어가지 않게 한다. 임시 로그는 커밋하지 않고 현재 작업이 만든 경로만 정리한다.
- 커밋은 사용자가 요청할 때만 `commit` 스킬로 한다. Red 상태에서 커밋하지 않는다.

## 완료 보고

- 수정한 파일과 대응하는 테스트 파일, 사이클별로 추가한 테스트 케이스
- 테스트를 추가하지 않은 파일과 그 이유(`~습니다`로 끝낸다)
- 최종 테스트 실행 결과(통과/실패 수). 실행하지 못했다면 그 이유
- 이슈 요구사항과 테스트의 대응, Red·Green 명령과 결과, 인접 경계 검증과 미확인 사항
